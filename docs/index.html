Your emails are safe

Nothing moves until you say so

Every run begins in dry-run mode. Your label structure is backed up before the first thread moves.

Email read-only 1. Backup Writes a spreadsheet to Drive. Never touches your emails.
Read-only 2. Analyze Reads your label structure. No changes are made.
Read-only 3. Dry Run Logs every planned move. Zero threads relabeled.
You decide 4. Execute Only runs after you manually set DRY_RUN: false.

Need to undo a migration? The script only adds and removes labels. Emails are never deleted. To reverse any migration, swap from and to in your plan and run again.

Quick start

Up and running in five minutes

No install. No CLI. Everything runs inside your Google account.

1

Open Google Apps Script

Go to script.google.com, click New Project, and name it "Gmail Reorganization".

2

Add the four script files

Go to File > New > Script. Create four files in this exact order and paste the contents from GitHub into each.

Apps Script: file order matters
// utils.gs must be first
1. utils.gs
2. backup.gs
3. analysis.gs
4. reorganization.gs
3

Authorize the script

Run any function (try quickStats). Google will ask for permission to read your Gmail. Follow the prompts and click Allow.

4

Back up first, always

Before changing anything, create an inventory of your current labels.

Apps Script
// Creates a spreadsheet with all your labels and counts
createBackup();

// Or just see a quick overview first
quickStats();
5

Plan, validate, and run

Edit ORGANIZATION_PLAN in reorganization.gs with your target structure, then follow this sequence.

Apps Script
// check your plan for errors
validatePlan();

// preview everything — DRY_RUN: true in CONFIG
main();

// set DRY_RUN: false, then run for real
main();

// check progress
showProgress();

Common concerns

Questions people ask at 2am

If you're nervous, read these before you run.

Will this delete any of my emails? +

No. The script only adds and removes labels on threads. Emails are never deleted and never read. Your content stays exactly where it is.

What if the script crashes halfway through? +

Google Apps Script has a six-minute execution limit. The script handles this automatically: it saves progress before stopping and picks up exactly where it left off the next time you run main(). No emails are at risk during an interruption.

I have tens of thousands of emails. Will this even work? +

Yes. The batch processing and auto-resume system was built for large mailboxes. If you hit Gmail rate limits, reduce BATCH_SIZE in the config and wait a few minutes. Run main() as many times as needed until showProgress() shows all migrations as Done.

What if I regret a migration after running it? +

Add a reverse migration: swap the from and to values in your plan and run again. Since no emails were deleted, everything can be put back.

Do I need to be a developer to use this? +

You need to copy files, paste code, and edit a config object. Beyond that, no programming experience needed. The hard part is deciding what structure you want, not running the code.

Does this send my email data anywhere? +

No. All code runs inside your Google account via Apps Script. Nothing is sent to any external server. The only thing written outside your Gmail is the optional backup spreadsheet, which also lives in your Google Drive.

Know before you run

What this tool does not do

Four things worth knowing before you start.

System labels (Inbox, Sent, Drafts, Spam) cannot be renamed or reorganized. Gmail does not expose these to Apps Script.

Label names cannot contain < > & or similar special characters. That's a Gmail restriction, not this script's.

Large mailboxes require multiple runs. The six-minute Apps Script execution limit is a Google platform constraint, but auto-resume handles it.

Heavy use can trigger Gmail rate limits. Wait a few minutes and run again. This is not an error you need to fix in the code.
